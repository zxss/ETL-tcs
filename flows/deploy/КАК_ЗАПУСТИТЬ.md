# Выкладка на VDS — как запустить

> Адрес сервера не хранится в репозитории (он публичный): `VDS=$(git remote get-url vds | sed 's/.*@//; s/:.*//')`.

**Подаём:** закоммиченную ветку, совпадающую с `/opt/etl-tcs.git/DEPLOY_BRANCH`
(сейчас `fix/contour-defects-2026-09-24`). Прочие ветки принимаются в репозиторий,
но рабочий каталог не трогают.

1. Новые ключи окружения — сначала в серверный `.env` (с бэкапом):
   `ssh root@$VDS 'cp -a /opt/etl-tcs/.env /root/env.backup-$(date +%Y%m%d)-<суть>'`
2. `git push vds <DEPLOY_BRANCH>`
3. Хук сам: `checkout -f`, переустановка зависимостей при изменении `requirements*`,
   сверка `.env` с `.env.example` (ложное срабатывание на `STAGE2_TRADE_TARGET` и
   `STAGE2_NOTIFY_LABEL` — они в `.env.tournament`), прогон тестов.

**Получаем:** `/opt/etl-tcs` на коммите ветки; в выводе хука — «тесты … OK».
**Самопроверка:** хук валит выкладку при падении тестов. После пуша:
`ssh root@$VDS 'git --git-dir=/opt/etl-tcs.git --work-tree=/opt/etl-tcs log --oneline -1'`

**Откат:** `ssh root@$VDS 'git --work-tree=/opt/etl-tcs --git-dir=/opt/etl-tcs.git checkout -f <прежний_коммит>'`
(подсказка хука «было → стало» печатает тот же коммит — известный косяк, прежний
коммит берите из `git log`).
Сменить ветку выкладки: `ssh root@… 'echo <ветка> > /opt/etl-tcs.git/DEPLOY_BRANCH'`.
