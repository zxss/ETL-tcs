# ETL — как запустить

**Подаём:** доступ к T-Invest API (`INVEST_TOKEN` в `.env`), PostgreSQL `market_data`.
**Запускаем:** `python main.py` (на VDS — systemd `etl-pipeline.timer`, ежедневно 19:30 МСК,
от пользователя `etl`, каталог `/opt/etl-tcs`).
**Получаем (шаги по порядку, сбой некритичного шага не валит конвейер):**

| шаг | модуль | результат |
|---|---|---|
| свечи 1D и 5M | `services/load_history.py` | `market_data`, `market_data_5m` |
| справочник | `services/load_instruments.py` | `instruments` (лот, шаг, шорт) |
| индексы | `services/load_index.py` | IMOEX в `market_data` |
| дивиденды | `services/load_dividends.py` | `dividends` (вперёд и история) |
| ключевая ставка | `services/load_macro.py` | `macro_rates` |
| 1D из 5M | `services/backfill_daily.py` | достройка дневных |
| бары основной сессии | `services/session_bars.py` | `market_data_session` — источник модели |
| валидация + прогноз | `services/run_validation.py`, `tft_forecast` | `forecasts` |

**Самопроверка:** в конце печатается «Pipeline Summary» по шагам; падение `etl` или
`forecast` — ненулевой код выхода. Гард свежести: бары сессии не старее последней
завершённой сессии.

Отдельно по расписанию (`/etc/cron.d/etl-news`, каждые 10 минут): сбор канала
новостей — `python -m services.news_tg` (`--stat` — что собрано). Разовый импорт
выгрузки Telegram: `python -m services.news_tg_import <каталог> --channel markettwits --dry-run`.
Кэш справочника вручную: `python -m services.load_instruments --force`.

**На VDS вручную:**
`ssh root@212.8.228.84 'sudo -u etl bash -c "cd /opt/etl-tcs && .venv/bin/python main.py"'`
Журнал таймера: `journalctl -u etl-pipeline.service --since today`.
