# Каркас: дорожная карта Phase 0 → Phase 3 (авторский синтез)

## Логика фазирования
Каждая фаза заканчивается **гейтом (gate)** — проверяемым критерием, без которого переход к следующей фазе запрещён. Это перенос практики stage-gate из R&D: главный риск квант-проекта не в том, что он не построится, а в том, что он построится и будет торговать шум.

## Phase 0 — Фундамент данных (0–3 мес)
**Тезис:** 70 % провалов квант-проектов закладываются здесь и проявляются через год.
- Выбор источника данных и **проверка его качества до покупки** (пробный период, сверка с независимым источником).
- Хранилище: колоночный формат (Parquet/Arrow) + движок запросов; партиционирование по дате и инструменту.
- Контур контроля качества (data QA) как код: детекция гэпов, пересечений bid>ask, нулевых объёмов, дубликатов, неправильных корп. действий, смещений часовых поясов.
- Два штампа времени на каждом событии: биржевой и локальный.
- **Анти-паттерн:** начинать с «напишем стратегию, данные потом». Стратегия на грязных данных — это генератор ложной уверенности.
- **Гейт 0:** любой исторический день воспроизводится бит-в-бит; отчёт QA зелёный; известна и задокументирована точность штампов времени.

## Phase 1 — Исследовательский контур (3–9 мес)
- Событийный бэктест-движок (свой или форк open-source), обязательно event-driven, не векторный, если стратегия чувствительна к исполнению.
- **Модель издержек — раньше стратегий.** Комиссия + спред + проскальзывание + impact. Модель издержек, написанная после стратегии, всегда подстраивается под неё.
- Протокол валидации: purged / combinatorial purged cross-validation, walk-forward, разбиение по режимам рынка.
- Протокол отбора с поправкой на множественное тестирование: Deflated Sharpe Ratio, Probability of Backtest Overfitting, White's Reality Check / Hansen SPA.
- **Реестр испытаний (trial registry):** фиксировать КАЖДУЮ проверенную гипотезу до её проверки. Без счётчика испытаний поправка на множественность невозможна, а значит невозможна и честная оценка.
- **Гейт 1:** есть ≥1 гипотеза, прибыльная после издержек, с DSR > 0 при честном числе испытаний, устойчивая на out-of-sample и в разных режимах.

## Phase 2 — Боевой контур малого капитала (9–18 мес)
- Исполнительный слой: машина состояний ордера, идемпотентность, восстановление после разрыва, OCO/защитные ордера.
- Pre-trade риск как **отдельный обязательный слой**, через который физически не пройти мимо: лимиты на размер, цену, позицию, частоту; kill switch.
- Сверка (reconciliation) с брокером: позиции, деньги, ордера — ежедневно и автоматически; расхождение = остановка торговли.
- Наблюдаемость: P50/P99/P99.9 латентности, журнал каждого решения с входными признаками (для последующего разбора).
- Торговля минимальным капиталом: цель фазы — не заработать, а **измерить расхождение симуляции и реальности**.
- **Гейт 2:** на горизонте ≥3 месяцев реальный P&L отличается от симулированного на величину в пределах заранее объявленного допуска; все расхождения объяснены.

## Phase 3 — Масштабирование (18–36 мес)
- Портфель стратегий: аллокация капитала, контроль корреляций, общий риск-бюджет.
- Снижение латентности — **только если это ограничение подтверждено измерением**, а не предположением.
- Расширение площадок и классов активов; унифицированная модель инструмента.
- Комплаенс-контур: журналирование, тестирование алгоритмов, процедуры перед изменением боевого кода.
- Организационная зрелость: разделение ролей ресёрч / инженерия / риск, code review для боевого кода, запрет на «горячие правки» в торговое время.
- **Гейт 3:** стратегии взаимно некоррелированы, риск управляется на уровне портфеля, замена одного человека не останавливает торговлю.

## Типовые ошибки распределения бюджета
| Фаза | Куда переинвестируют | Куда недоинвестируют |
|---|---|---|
| 0 | Красивые дашборды | Качество данных, штампы времени |
| 1 | Сложность моделей (DL вместо линейных) | Модель издержек, протокол валидации |
| 2 | Скорость исполнения | Сверка, восстановление после сбоя, kill switch |
| 3 | Новые рынки | Контроль корреляций, операционная устойчивость |
