# Т-Банк Пульс как источник данных для прогноза — разбор осуществимости

Запрос 23.09.2026: есть ли у Пульса API, можно ли выгрузить данные об авторах /
их сделках / доходности и использовать в прогнозе на демо-счёте. Ниже —
проверенный разбор по трём пунктам. Проверка эндпоинтов сделана вживую
(один read-запрос к официальному корпоративному профилю), не по памяти.

## 1. Наличие API — да, но неофициальный

Пульс работает на **внутреннем REST API**, который использует его же веб-фронт.
Это НЕ официальный T-Invest API (тот, на котором стоит r4) — в официальном API
социальных данных нет вообще. Живые эндпоинты (проверено 23.09.2026, хост после
ребрендинга — `www.tbank.ru`, путь прежний):

| что отдаёт | эндпоинт (GET) |
|---|---|
| профиль автора по нику | `www.tbank.ru/api/invest-gw/social/v1/profile/nickname/{nick}` |
| посты по тикеру | `…/social/v1/post/instrument/{ticker}?cursor=&limit=50` |
| посты по id автора | `…/social/v1/post/user/{user_id}?cursor=` |

* Авторизация для чтения **не требуется** (`baseTariffCategory: unauthorized`
  отдаёт 200). Пагинация — курсором. Есть готовая python-обёртка `tpulse` (PyPI).
* Профиль автора в поле `statistics` отдаёт: **`yearRelativeYield`** (доходность
  за год, %), `totalAmountRange` (размер портфеля — вилкой, не точно),
  `monthOperationsCount` (число операций за месяц), число подписчиков, список
  стратегий автоследования.

**Риски именно из-за неофициальности:**
* Эндпоинт недокументирован — может измениться/закрыться без предупреждения, SLA
  нет. Для системы, которая на этих данных ТОРГУЕТ (пусть и на демо), это тихая
  точка отказа.
* Скрейпинг почти наверняка против пользовательского соглашения T-Банка. Для
  разовой разведки на демо это малорисково, но постоянный сборщик — это уже
  осознанное решение, которое принимаешь ты, не я по своей инициативе.

## 2. Возможность выгрузки — технически легко, но данных о СДЕЛКАХ почти нет

Технически — тривиально: JSON, без авторизации, курсорная пагинация; сообщество
уже собирало 500 тыс.+ постов. Но важное ограничение по содержанию:

* **Ленты реальных сделок (buy/sell с ценой/временем/объёмом) в API НЕТ.**
  Доступно только: тексты постов (маркетинговые), агрегатная годовая доходность
  `yearRelativeYield`, счётчик операций, размер портфеля вилкой. То есть «их
  сделки» из запроса выгрузить нельзя — только то, что автор сам опубликовал
  постом, плюс одна итоговая цифра доходности.
* Качество цифры доходности низкое: самоотбор и «ошибка выжившего» (слитые счета
  исчезают, показывают винрейт-витрину), портфель — вилкой, доходность считает
  платформа по своим правилам.
* Приватность/публичный репозиторий: `zxss/ETL-tcs` публичный. Ники авторов +
  их финансы — персональные данные; в git их класть нельзя (как и тексты
  markettwits — та же линия). Хранить только производные агрегаты, в БД, не в
  коде.

## 3. Прогнозная ценность — прямых свидетельств «за» нет, есть одно «против»

Есть уже проведённое независимое исследование ровно этих данных (artydev.ru,
529 069 постов, ~3 500 авторов с 30+ постами, доходности за 2021):

* **Зависимости между популярностью автора и его доходностью нет вообще** — ни
  для кого, включая аккаунты с 10 000+ подписчиков.
* Топ-авторы в основном **проигрывают рынку**, часть закрывает год в убыток;
  из стратегий автоследования популярных авторов **7 из 11 в минусе**.
* Авторы, продвигающие платные телеграм-каналы, — с такой же плохой доходностью.

Это ровно то, что мы независимо получили по всем 180 испытаниям этого проекта:
новости markettwits, Polymarket, политические новости — связь в лучшем случае
одновременная, прогноза после издержек нет. Наивная гипотеза «повторять за
популярными/доходными авторами» почти наверняка провалится и здесь.

**Но есть одна честно НЕ проверенная гипотеза, отличная от наивной.** Раз толпа
Пульса систематически неправа, ценность может быть в **контрсигнале**: не
следовать за розницей, а гасить её экстремумы — когда суммарный тон/активность
постов Пульса по бумаге упирается в крайность, ставить ПРОТИВ. Это отдельная
проверяемая гипотеза, которую внешнее исследование не делало (оно проверяло
только «коррелирует ли популярность с доходностью»). Именно её имело бы смысл
проверить, а не копирование авторов.

## Рекомендация

1. **API есть, выгрузка возможна** — но без ленты сделок; максимум полезного
   сигнала — это агрегат тона/активности постов по тикеру за день (как розничный
   sentiment-индекс), плюс, отдельно, доходности авторов как контекст.
2. **Наивный сигнал «за авторами» тестировать не стоит** — против него и внешние
   данные, и все 180 наших испытаний.
3. **Единственное, что стоит проверить, — контрариан-сигнал** на дневном
   розничном тоне Пульса по бумаге: строится ретро-индекс тона/активности, строго
   до бара решения, и тем же харнессом (Холм, CPCV, издержки, DoR-гейт, отложенная
   выборка), что и всё остальное. С теми же оговорками: неофициальный API как
   точка отказа live-контура, ники+финансы не в git.

Если скажешь — соберу ретро-выборку постов по нашему тикер-универсу и прогоню
предзарегистрированный контрариан-тест на демо-контуре. Постоянный live-сборщик
поверх неофициального API — отдельное твоё решение из-за соглашения T-Банка.
